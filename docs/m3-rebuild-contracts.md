# Module 3 contracts

The sole architecture consists of two independently executable workflows.
`contracts.py` owns the authoritative shallow model extraction definition and
strict application output schema. `provider_schema()` derives provider constraints
by removing only `additionalProperties`; required fields and types are retained,
while local validation still enforces closed objects. No independent provider
schema is maintained.

## Corporate conversion (entirely deterministic)

Input: schema 1.0 corporate_structure_onboarding with company_name, data_status
and corporate_tree. Nodes preserve exact id/name/role/is_guarantor, optional
record_type, hierarchy, sibling order and numeric ownership percentage. Duplicate
IDs, malformed trees/flags, unknown roles, invalid/non-finite percentages fail.

Output: reference schema 2.0 artifact with purpose, disclaimer, instructions,
visual_spec, one company, flat nodes/boxes, ownership links, connector paths,
legend, ownership tree and provenance. HCA uses 1440 x 1080 and reference boxes;
other trees use disjoint 260 px leaf slots and 200 px levels, expanding the canvas
without shrinking readable nodes. Geometry validation rejects overlaps, wrong
endpoints, single-child jogs and unrelated connector crossings.
Filename: Visualized [Company Name] Corporate structure.json.
Submitted simulated assumptions are authoritative only within the educational
case, never independently verified real legal/guarantor facts.

## Management facts and credit judgments (Milestone 3)

Only the admitted M3 canonical packet is model input. The router retains ordered
cover/executive-section passages and adjacent chunks under their original IDs.
Root model fields: roster_date, roster_source_id, roster_quote, executives,
facts, judgments, overall_assessment. Each executive
has name, position, appointment_date, source_id, quote, prior_internal_roles,
external_recruitment_quote and external_source_id. Each prior role has position,
start_date, end_date, source_id and quote. ISO year/month/day strings preserve
precision; empty strings mean unavailable. Executive and role records accept
supporting_citations for fragments spanning canonical passages. Each fact has an
identity, an executive (or company scope), an extractive statement and quotations.
Each judgment references accepted fact IDs and supplies a credit_positive,
credit_negative, neutral or insufficient_evidence signal, credit mechanism and
uncertainties. The model provides the balanced overall assessment, uncertainty
and missing information. Categories organize analysis without prescribing direction.
No validator decisions, coordinates, credit scores or runtime diagnostics are
generated by the model. The response contract is m3-management-response-2.0.

## Application validation and assembly

Python validates strict types, source/quote resolution, roster identity and
coverage, role/date binding, employer attribution, dates and semantic consistency.
Quotation matching is separate from inference support. Outside-employer roles are
rejected; ambiguous scope does not establish internal succession. Roster table
boundaries, unparsed content, duplicates, wraps and biography reconciliation
control coverage. Recognizing one row never proves an entire roster complete.

Final schema m3-management-assessment-3.0 contains company/filing/source identity,
roster_date, inclusive three-year review_window, profiles with disclosed date
precision, coverage, observations, overall assessment, rejection records,
limitations and one deduplicated citation table. Python calculates tenure bounds
from disclosed precision and the roster date. It checks quotations, employer/date
binding, roster coverage, fact excerpts and judgment references. Model judgment
IDs survive as observation IDs. Python does not assign qualitative credit
directions or override a supported neutral judgment. Rejected facts/judgments
and invalid overall references remain explicit; rejected dependencies cannot
support a validated overall conclusion. Identity, title, appointment, each prior
role, each quoted fact and each qualitative judgment have independent outcomes;
one failure does not reject the profile. Historical v1/v2 artifacts remain
readable under their original schemas and are not reinterpreted as current review.

M3-only matching preserves raw quotations and original source spans. It permits
whitespace, equivalent typography and a closed set of PDF word-boundary repairs.
No edit-distance matching, spelling correction, name/date/number/title change,
negation removal or cross-passage relocation is permitted. Each successful match
records document ID/SHA-256, physical page, canonical passage ID, original text,
matching method and character offsets. Failed citations remain in the claim ledger;
valid explicitly submitted alternative fragments can support a qualified claim.

## Normal orchestration, persistence and downstream claims

Normal `SourcePackage.module3` selections identify sources that pass through shared
admission; no runner/CLI file side path, architecture selector or legacy fallback
exists. Missing inputs or missing authorized extraction yield independent
`not_attempted` states. The persisted shared-router packet carries typed corporate
evidence and canonical narrative passages with document IDs and hashes. Previously
generated rebuild manifests remain readable through artifact adapters, not as
inputs to a new normal run. Independent artifact/diagnostic files record schemas,
status and byte hashes; failure never suppresses a valid sibling. Parsing/schema/
quotation/support outcomes, request attempt, available HTTP status, answer return,
model/configuration/versions and tokens remain distinct. Unavailable transport or
usage values stay null.

The specialist runs through AgentRuntime, LLMClient, PromptRegistry and common
AgentRun/ModelRun/audit persistence. Its exact rendered prompt, raw response,
schema-parsed response and evidence-validation report are saved. A selectable
LLMBackend supports offline replay or an explicitly authorized Vertex call; the
former private SDK adapter and two-request harness reject live execution.

BO/SO consume the actual typed components. Dedicated ManagementMemoClaim records
refer to observation_id and citation_ids, preserving the bounded statement and
category. The actual partial memo renderer displays these claims and citations;
its validator rejects unsupported statement/reference changes. No legacy
hypothesis, subjective management score or verified legal graph is constructed.
Validator 7 now runs as `m3_validator_7` through the same shared runtime/audit path.
It reviews reasonableness, qualifications and excess inference independently of
factual matching. It returns accepted/qualified/unsupported outcomes, specific
reasons, surviving claim references and separate reviewed wording. Original model
text remains preserved. Overall conclusions can reference only surviving judgments.
No review backend means no invented qualitative acceptance. Scope is three principal
individual assessments plus a team assessment when disclosed, not seven required
individual judgments. Milestone 4 uses offline reviewer fixtures only; live reviewer
performance remains unverified. Observation-level downstream challenge/revision and
fuller uncertainty consumption remain gaps. The final credit-decision stage remains
incomplete and explicitly unapproved.
